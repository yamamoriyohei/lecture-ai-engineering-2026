### 実装：承認付きの save_learning_log

- やったこと：
  - `app/tools.py` に `save_learning_log(title, content)` を作った。`learning_log/` に Markdown で保存する。ファイル名に日時を付けて上書きを防ぎ、題名か本文が空なら保存しない
  - `app/agent.py` で `requires_approval=True` を付けて登録し、`output_type=[str, DeferredToolRequests]` にした
  - 承認待ちで止まったら、ツール名と引数（保存する題名と本文）を表示して `[y/N]` で聞く。`y` なら承認し、それ以外（空 Enter を含む）は `ToolDenied` で拒否して、`deferred_tool_results` を渡して続きを実行する（`run_with_approval`）。保存は取り消しにくいので、既定は「保存しない」にした
  - API キーなしで動くテスト `tests/test_learning_log.py` を追加した（TestModel を使用）。確かめていること：
    - 承認待ちで止まり、その時点ではファイルが作られていない
    - `y` で保存され、`n` や空 Enter では保存されない
    - 拒否したことがツールの結果としてモデルに伝わる
    - 承認前後の LLM 呼び出しが合算される
  - 既存の `tests/test_agent.py` も直した。「登録したツールを全部呼ぶ」テストが承認待ちで止まり、「呼び出しの数＝結果の数」が合わなくなったため、承認が要らないツールだけを呼ぶ形にした
- 結果：
  - `uv run pytest -q` で 26 件すべて通った
  - 承認した場合：`search_glossary({'query': 'LoRA'})` で定義を確認したあと、`save_learning_log(title='LoRAについての学習記録', content='…')` が呼ばれて承認待ちで止まった。題名と本文が表示され、`y` で `learning_log/20261103-145341_LoRAについての学習記録.md` が作られた
  - 拒否した場合：同じ流れで止まり、`n` を返すと `save_learning_log -> 利用者が保存を許可しませんでした。` がモデルに戻った。モデルは「利用者の確認により保存は行われませんでした」と答え、ファイルは作られなかった
  - 実行してみて分かった不具合を 2 つ直した
    - 回数の数え漏れ：承認後の `[usage]` が `requests=1` と表示された。実際は「検索 → 保存の依頼 → 承認後の回答」の 3 回だった。続きの実行は別の `run_sync` なので、前の実行の回数が数えられていなかった。`usage=result.usage` を渡して合算するように直した
    - 見出しの重複：保存したファイルで見出しが 2 重になった。モデルが本文の先頭にも `# 題名` を書いたためで、docstring に「題名の見出しは自動で付くので content には書かない」と足し、重複した見出しを取り除くようにした
- 気づき・疑問：
  - 承認を挟むと、エージェントの実行は「1 回の呼び出しで終わる」ものではなくなる。いったん止まり、人の判断を受け取ってから会話の履歴ごと再開する形になる。使用量の集計やテストも、この 2 段階を前提に書き直す必要があった
  - 承認画面にツールの引数がそのまま出るので、人は「何が保存されるか」を見てから決められる。逆に言えば、引数を表示せずに「保存してよいですか？」とだけ聞くと、承認は形だけになる
  - モデルは「記録して」と頼まれると、保存の前に `search_glossary` で用語を確認してから本文を書いた。INSTRUCTIONS の「用語を答える前に必ず用語集を確認する」が、保存の内容にも効いている
  - 疑問：今回は全部の保存に確認を求めたが、保存の回数が増えると確認が面倒になり、内容を読まずに `y` を押すようになりそう。どの操作に確認を求め、どこから自動にするかの線引きは、実際の運用ではどう決めるのか

### 発展（a）：同じエージェントを Google の ADK で組み立て直す

- やったこと：
  - `adk_agent/glossary_agent/agent.py` と `__init__.py`（`from . import agent` の 1 行）を作った。`app/` のファイルは変えていない
  - 指示は `app.agent.INSTRUCTIONS`、ツールは `app.tools` の `search_glossary`・`get_lecture_summary`・`make_quiz` をそのまま使った。モデルも同じ `app.config.MODEL`（`gemini-3.5-flash-lite`）にした。承認付きの `save_learning_log` は範囲外なので渡していない
  - `PYTHONPATH=. uv run --with google-adk adk run adk_agent/glossary_agent` で起動し（ADK 2.13.0）、演習と同じ 3 問を続けて入力した

  ```python
  from google.adk.agents import Agent

  root_agent = Agent(
      model=MODEL,
      name="glossary_agent",
      description="AIE2026 の用語集と各回の要点を使って答える学習支援エージェント",
      instruction=INSTRUCTIONS,
      tools=[tools.search_glossary, tools.get_lecture_summary, tools.make_quiz],

  ```

- 結果（書き方の比較）：

  | | Pydantic AI（`app/agent.py`） | ADK（`adk_agent/glossary_agent/agent.py`） |
  |---|---|---|
  | エージェントを作る | `Agent(instructions=...)` | `Agent(name=..., model=..., instruction=...)`。`name` が必須 |
  | ツールを渡す | 作ったあとに `agent.tool_plain(関数)` で 1 つずつ登録 | 作るときに `tools=[関数, ...]` でまとめて渡す |
  | ツールの説明文 | 関数の docstring と型ヒント | 同じ（ADK も docstring と型ヒントから引数の JSON スキーマを作る） |
  | モデル | 実行時に `run_sync(..., model=...)` で渡す | 定義のときに文字列で決める |
  | 実行 | 自分のコードから `run_sync()` を呼ぶ。1 回の実行で 1 問 | `adk run` が `root_agent` を探して動かす。対話形式で、同じセッションの中では会話の履歴が続く |
  | ツール呼び出しの確認 | `--trace` を自分で実装して表示 | `adk run` の画面には出ない。`adk web` の開発用画面やログで見る |

- 結果（回答の比較）：
  - lecNN-start タグ：「各回の演習開始時点のコードに付けられている Git タグ（例：`lec03-start`）」「前の回が終わっていなくてもこのタグからブランチを作れば始められる」と、Pydantic AI 版とほぼ同じ文面で答えた。用語集の定義そのままの言い回しなので、`search_glossary` を呼んでいると考えられる
  - LoRA と QLoRA の違い：用語集の「2つの小さな低ランク行列」「4ビットなどに量子化してメモリを節約」という定義に沿って答え、「関連する回：第2回」も付けた。Pydantic AI 版と内容は同じ
  - 確認問題：第2回から「QLoRA」が出題され、答えは伏せられた（Pydantic AI 版では「教師ありファインチューニング（SFT）」。`make_quiz` が用語をランダムに選ぶため）
  - INSTRUCTIONS の「関係する回を示す」「答えそのものは書かない」も守られており、指示とツールが同じなら、フレームワークを替えても回答はほとんど変わらなかった
- 気づき・疑問：
  - 回答を決めているのは指示・ツールの説明文・モデルで、フレームワークはその間の「モデルを呼ぶ → ツールを実行する → 結果を返す」ループを回す部分だと実感した。だから同じ部品を渡せば、同じように振る舞う
  - 違いが出たのは周辺の作りだった。Pydantic AI は「ライブラリを自分のコードから呼ぶ」作りで、モデルを実行時に差し替えられるので、TestModel を使ったテストが書きやすい。ADK は「決まった場所に `root_agent` を置くと、ADK の実行環境が動かしてくれる」作りで、対話の画面・セッション・開発用の Web 画面が最初から付いてくる。その分、モデルがエージェントの定義に固定され、テストで偽のモデルに替える方法は別に調べる必要がある
  - `adk run` は 3 問を同じセッションで続けて聞けた。第1回の宿題で自分で実装した「会話履歴を保つ」機能が、ADK では最初から入っている
  - 確認問題の回答に「答えは利用者の方が答えた後に見せることができます」とあった。docstring の「利用者が答えるまで見せないこと」という、モデル向けの指示を利用者にそのまま言ってしまっている。ツールの説明文はモデルへの指示だが、その言葉が回答に漏れることもあると分かった
  - 起動時に `[EXPERIMENTAL]` の警告が出た。ADK は 2.0 で大きく変わったばかりで、機能によっては今後も変わりうる
  - 疑問：ADK で `save_learning_log` のような承認付きのツールを作るとき、Pydantic AI の `requires_approval=True` にあたる仕組みはどう書くのか。また、`adk web` ではツール呼び出しがどう見えるのか、次に確かめたい
